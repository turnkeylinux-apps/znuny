# Znuny v19 testing

## Product and compatibility boundary

This repository builds the separate TurnKey Znuny appliance. It does not ship
or claim the current commercial OTRS product. Debian 13 supplies binary package
`otrs2` from source package `znuny` in signed `trixie-backports` non-free.
Debian's metadata identifies `https://github.com/znuny/Znuny` as the project
homepage.

Debian preserves several historical compatibility interfaces. The appliance
therefore intentionally retains the `otrs2` binary package, `otrs` Unix user
and database, `/usr/share/otrs`, `/etc/otrs`, `/run/otrs`,
`otrs.Console.pl`, `/etc/cron.d/otrs2`, and the appliance-internal `/otrs`
application route. TurnKey-owned identities use `znuny`: the repository slug,
release name, firstboot hooks and prompts, update command, state directory,
landing page, tests, and documentation.

The new `znuny` slug is a replacement product boundary. An in-place upgrade
from a v18 appliance installed under the `otrs` slug is **not supported or
tested** by this migration. No TKLBAM profile compatibility, Hub migration, or
automatic cross-slug restore claim is made. Operators should deploy a fresh
Znuny v19 appliance and perform an application-level migration that they have
validated for their data and integrations.

## Dependency source and updates

Updates use the inherited Core 19 Debian 13 archive trust and the appliance's
explicit `trixie-backports` source with `non-free` enabled.
`turnkey-znuny-update --check` reports the installed version, APT candidate,
channel, and status. `--apply --dry-run` resolves the signed Debian
transaction; `--apply` installs an available update, rebuilds application
configuration, clears the application cache, and restarts the daemon and
Apache.

Znuny publishes its support matrix and vulnerability disclosure policy at
`https://github.com/znuny/Znuny/security`. Security reports go to
`security@znuny.org`.

## Primary-flow crosswalk

| Criterion | `tests/v19.sh` proof |
| --- | --- |
| Package source | Requires Debian's `otrs2` binary, verifies source package `znuny`, records the Trixie source decision, and checks the installed dpkg version. |
| Normal firstboot | Requires the renamed `40znuny` inithook to have completed and authenticates with its seeded application password. |
| Agent web login | Submits the `root@localhost` credentials through the HTTPS agent interface and requires an authenticated dashboard response. |
| Queue create/read | Creates a uniquely named queue with the supported console command and reads it back through the queue list. |
| Ticket create/read | Requires the backports package's bundled Sisimai 4.25.16 `Data.pm` and filter to compile, feeds a synthetic non-bounce RFC 822 message through `Maint::PostMaster::Read`, locates the resulting ticket in MariaDB, and reads the ticket and first article with `Maint::Ticket::Dump`. |
| Database and restart persistence | Runs Znuny's database check, restarts MariaDB and Apache, then proves the created ticket and a fresh authenticated session still work. |
| Jobs | Requires the Debian cron definition, restarts the Znuny daemon, and lists its scheduler worker. |
| Mail | Exercises inbound PostMaster parsing, inspects the application mail queue, requires active Postfix, and verifies its loopback binding. |
| Maintained updates | Runs the TurnKey Znuny updater check and dry-run apply against Debian's signed package channel. |
| Identity | Runs `tests/verify-identity.sh` to enforce the Znuny-facing name while allowing only documented Debian/runtime compatibility names. |
| Machine-readable result | Writes exactly the seven v19 result keys after all assertions pass. |

Application-created queue and ticket fixtures live only in the disposable
runtime container. The isolated harness removes that container, its image,
the configured root, and staged source after a passing run while retaining the
sanitized report, log, and hashes.

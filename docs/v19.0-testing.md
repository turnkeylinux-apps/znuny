# OTRS/Znuny v19 testing

## Dependency source

Debian 13 supplies `otrs2` version `6.5.15-2` from source package
`znuny`. Znuny marks the 6.5 LTS line as supported for security updates, so the
appliance uses the Debian package rather than adding an upstream source
installer. The probed Debian package SHA-256 is
`6e4948a2b55d23167554800b096e7e2c2015f0cd0ef83467db15b1886bf1a0a4`.

Updates use the inherited Core 19 Debian 13 repositories and archive trust.
`turnkey-otrs-update --check` reports the installed version, APT candidate,
channel, and status. `--apply --dry-run` resolves the signed Debian transaction;
`--apply` installs an available update, rebuilds application configuration,
clears the application cache, and restarts the daemon and Apache.

Znuny publishes its support matrix and vulnerability disclosure policy at
`https://github.com/znuny/Znuny/security`. Security reports go to
`security@znuny.org`.

## Primary-flow crosswalk

| Criterion | `tests/v19.sh` proof |
| --- | --- |
| Package source | Require the Debian package, the recorded Trixie source decision, version `6.5.15-2` or newer, and a matching dpkg record. |
| Agent web login | Submit the `root@localhost` credentials through the HTTPS agent interface and require an authenticated dashboard response. |
| Queue create/read | Create a uniquely named queue with the supported console command and read it back through the queue list. |
| Ticket create/read | Feed a synthetic RFC 822 message through `Maint::PostMaster::Read`, locate the resulting ticket in MariaDB, and read the ticket and first article with `Maint::Ticket::Dump`. |
| Database | Query the installed users table and run Znuny's database check command. |
| Jobs | Require the Debian cron definition, start and inspect the Znuny daemon, and list its scheduler worker. |
| Mail | Exercise inbound PostMaster parsing, inspect the application mail queue, require active Postfix, and verify its loopback binding. |
| Maintained updates | Run updater check and dry-run apply against Debian's signed package channel. |
| Machine-readable result | Emit exactly the seven v19 result keys after all assertions pass. |

## Evidence state

Candidate gates cover shell and Python syntax, current package paths and
console commands, executable modes, the exact result schema, Debian artifact
checksum, documentation formatting, and legacy dependency removal. The exact
appliance run is left to independent Wave 2 validation because the shared
runner has a known infrastructure failure. This consumes zero product-fix
loops.

Product-fix loops used: 0 of 3.
